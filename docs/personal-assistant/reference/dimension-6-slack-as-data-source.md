### 1.2 Unread Message Detection

A significant limitation: the `unread_count` and `unread_count_display` fields are included for **DM conversations only** in both `conversations.list` and `conversations.info`. They are not available for public or private channels.

To get unread counts for channels, alternatives include:
- **`client.counts`** (undocumented/internal API): Returns unread counts for all channels and IMs.
- **Manual calculation**: Compare `conversations.history` results against the `last_read` timestamp from `conversations.info`.

- **Source**: [conversations.list method | Slack Developer Docs](https://docs.slack.dev/reference/methods/conversations.list/)
- **Date accessed**: 2026-03-26

- **Source**: [conversations.info method | Slack Developer Docs](https://docs.slack.dev/reference/methods/conversations.info/)
- **Date accessed**: 2026-03-26

- **Quality note**: The `client.counts` API is undocumented and may change without notice.

### 1.3 Mention Detection

The Events API `app_mention` event fires whenever someone mentions the app/bot in a message. For detecting mentions of a specific user (not the app), `search.messages` with the query `from:<user>` or `<@USER_ID>` can be used.

- **Source**: [The Events API | Slack Developer Docs](https://docs.slack.dev/apis/events-api/)

## 2. Bot Token vs User Token API Differences

### 2.1 Token Types

| Token Type | Prefix | Identity | Persistence |
|-----------|--------|----------|-------------|
| Bot token | `xoxb-` | Tied to the app, not a user | Stays installed even when installing user is deactivated |
| User token | `xoxp-` | Tied to a specific user's identity and access | Follows user's workspace access |

- **Source**: [Tokens | Slack Developer Docs](https://docs.slack.dev/authentication/tokens/)
- **Date accessed**: 2026-03-26

### 2.2 Access Differences

- **Bot tokens**: Can access channels the bot has been invited to. For `conversations.replies`, bot tokens work for DMs and multi-party DMs but **lack sufficient permissions** for public and private channel threads.
- **User tokens**: Have the same access as the user -- can access public channels they are not members of (with `channels:history` scope). Write actions are performed as the user.
- Both token types **share the same rate limit pool** per app per workspace.

- **Source**: [conversations.replies method | Slack Developer Docs](https://docs.slack.dev/reference/methods/conversations.replies/)
- **Date accessed**: 2026-03-26

- **Source**: [Rate limits | Slack Developer Docs](https://docs.slack.dev/apis/web-api/rate-limits/)
- **Date accessed**: 2026-03-26

## 3. Slack Events API for Real-Time Monitoring

### 3.1 How It Works

The Events API is a subscription-based system where Slack sends HTTP requests to your app when subscribed events occur. It replaces the legacy Real Time Messaging (RTM) API.

Two delivery options:
- **Socket Mode**: WebSocket connection; no public URL needed.
- **HTTP endpoint**: Your server receives HTTP POST requests from Slack.

- **Source**: [The Events API | Slack Developer Docs](https://docs.slack.dev/apis/events-api/)
- **Date accessed**: 2026-03-26

### 3.2 Key Event Types for Monitoring

| Event | Description |
|-------|-------------|
| `app_mention` | Someone mentions the app/bot in a message |
| `message.channels` | New message in a public channel |
| `message.groups` | New message in a private channel |
| `message.im` | New direct message |
| `message.mpim` | New multi-party DM |
| `reaction_added` | A reaction emoji was added to a message |
| `member_joined_channel` | A user joined a channel |

- **Source**: [The Events API | Slack Developer Docs](https://docs.slack.dev/apis/events-api/)
- **Date accessed**: 2026-03-26

- **Source**: [message event | Slack API](https://api.slack.com/events/message)
- **Date accessed**: 2026-03-26

### 3.3 Legacy RTM API

The Real Time Messaging API uses WebSockets for real-time events. However:
- **Granular permission apps cannot use the RTM API**.
- Classic apps can still use it but may no longer be created and are being deprecated.
- Slack recommends the Events API instead.

- **Source**: [Legacy: Real Time Messaging API | Slack](https://api.slack.com/legacy/rtm)

## 4. Rate Limits and Data Access Constraints

### 4.1 Rate Limit Tiers

Rate limits are enforced per API method, per app, per workspace.

For Marketplace and internal customer-built apps, `conversations.history` has **Tier 3** rate limits.

### 4.2 Critical Change for Non-Marketplace Apps (2025-2026)

As of a May 2025 announcement, non-Marketplace (unlisted, commercially distributed) apps face severely reduced limits for `conversations.history` and `conversations.replies`:
- **1 request per minute**
- **Maximum 15 objects per request**
- Effective immediately for new unlisted apps/installations.
- **Beginning March 3, 2026**, existing installations are also subject to these limits.

Rationale: These methods "have the potential to exfiltrate large amounts of sensitive conversational data" in the hands of unvetted applications.

**Marketplace apps and internal customer-built apps are not affected.**

- **Source**: [Rate limit changes for non-Marketplace apps - Slack Developer Docs](https://docs.slack.dev/changelog/2025/05/29/rate-limit-changes-for-non-marketplace-apps/)
- **Date accessed**: 2026-03-26

- **Source**: [Rate limits | Slack Developer Docs](https://docs.slack.dev/apis/web-api/rate-limits/)
- **Date accessed**: 2026-03-26
- **Quality note**: This is a significant constraint for personal/custom monitoring tools not published to the Marketplace.

### 4.3 Rate Limit Handling

Exceeding limits returns HTTP 429 with a `Retry-After` header. Only the specific method for that app in that workspace is throttled; other methods and other workspaces are unaffected.

- **Source**: [Rate limits | Slack Developer Docs](https://docs.slack.dev/apis/web-api/rate-limits/)
- **Date accessed**: 2026-03-26

## 8. Privacy Implications of Slack Monitoring

### 8.1 Employer as Data Controller

Slack considers itself a "processor" of data while the employer is the data "controller." This means workspace owners and administrators can access virtually all communications, including messages employees consider private.

- **Source**: [The employee's guide to Slack's privacy policy | 1Password](https://1password.com/blog/employees-guide-to-slacks-privacy-policy)
- **Date accessed**: 2026-03-26

### 8.2 Data Export Capabilities by Plan

| Plan | Admin Access |
|------|-------------|
| Free / Pro | Public channel export always available; all-workspace export only under limited circumstances |
| Business+ | Public channel export; compliance features |
| Enterprise Grid | Discovery API access; third-party eDiscovery/DLP tools; private channel and DM content with compliance exports enabled |

- **Source**: [Does Slack Protect Data? A Guide to Slack Privacy Concerns | Mimecast](https://www.mimecast.com/blog/slack-privacy-concerns/)

### 8.3 Admin Visibility into DMs

Whether admins can access DMs depends on the Slack plan, workspace settings, and internal policies. On Free/Pro plans, accessing DMs requires submitting a request to Slack with a valid reason (legal/compliance). On Enterprise Grid with compliance exports enabled, admin access to DMs is direct.

- **Source**: [Can Slack admins read your DMs? | NordPass](https://nordpass.com/blog/can-slack-admins-read-dms/)
- **Date accessed**: 2026-03-26

### 8.4 Encryption Limitations

- Slack encrypts data in transit (TLS 1.2) and at rest (AES256, FIPS 140-2 compliant).
- Slack does **not** offer end-to-end encryption.
- Slack holds encryption keys and can decrypt messages (must comply with law enforcement requests).

- **Source**: [Is Slack Encrypted? Understanding Slack Security and Privacy](https://trueconf.com/blog/reviews-comparisons/is-slack-encrypted)
- **Date accessed**: 2026-03-26

### 8.5 Bot/App Data Access Risks

- Slack offers 2,600+ apps/integrations; any could potentially open a back door for data exfiltration.
- Organizations should question whether each integration needs the access it requests.
- Bots and custom applications can create "unmanaged risks" and "parallel infrastructure" not under security policy controls.
- By default, Slack stores messages and files indefinitely unless custom retention settings are applied.

- **Source**: [Slack Security Concerns: What Technical Teams Need to Know](https://www.reco.ai/hub/slack-security-concerns)
- **Date accessed**: 2026-03-26

- **Source**: [Slack Security: 8 Key Risks and Best Practices for Admins & Employees](https://www.reco.ai/learn/slack-security)
- **Date accessed**: 2026-03-26

### 8.6 Implications for a Personal Assistant

A personal assistant monitoring Slack would need to consider:
1. **User token approach**: Uses the user's own identity and access. No additional permissions beyond what the user already has. Least controversial from a privacy perspective.
2. **Bot token approach**: Requires explicit installation and admin approval. Bot can only access channels it is invited to. Actions are attributable to the bot, not the user.
3. **Workspace admin visibility**: Admins can see which apps are installed and may audit their activity.
4. **Data retention**: Any data cached or stored by the assistant inherits the same compliance obligations as the Slack workspace.

## 9. Data Gaps and Unfound Items

1. **Reaction/emoji patterns signaling action needed**: No API specifically interprets emoji patterns as action signals. Custom logic would be needed to interpret specific reactions (e.g., an "eyes" emoji meaning "needs review") as action items. The `reactions.list` and `reactions.get` API methods can retrieve reactions on messages.

2. **Prioritization of unread messages**: Slack's API does not provide any built-in prioritization of unread messages. The Activity view's filter UI in the Slack client offers some filtering, but this is not exposed via API. Prioritization would need to be implemented client-side based on heuristics (sender importance, channel priority, @-mentions, keywords).

3. **Specific per-tier rate limit numbers**: The search results reference "Tier 2" and "Tier 3" but the exact requests-per-minute values for each tier were not directly surfaced. The Slack documentation page lists them but the page content was not fetched.

4. **Slack Connect (cross-organization) monitoring**: No specific findings on how Slack Connect channels interact with monitoring APIs. This would be relevant for users in multiple organizations.
