## Section B: Open-Source Frameworks for Building Multi-Source Aggregators

### 1. n8n (Fair-code, self-hostable)

- **What:** Workflow automation platform with 400+ integrations, native AI capabilities, and bidirectional MCP support.
- **Relevance:** Can serve as the orchestration layer for a multi-source aggregator. Any workflow can be exposed as an MCP tool. Built-in connectors for Jira, GitHub, Google Workspace, Slack.
- **MCP support:** Yes — both MCP Server (expose workflows as tools) and MCP Client (consume external MCP servers).
- **Pricing:** Community Edition is free (self-hosted). Paid starts at €20/month.
- **Effort estimate:** Low-medium. Visual workflow builder means the aggregation logic can be built without code. AI agent nodes can summarize the aggregated data.
- **Source URLs:**
  - https://n8n.io/ (accessed 2026-03-26)
  - https://www.n8n-mcp.com/ (accessed 2026-03-26)
  - https://github.com/n8n-io/n8n (accessed 2026-03-26)

### 2. LangGraph (LangChain ecosystem)

- **What:** Open-source library for building stateful, multi-actor LLM applications with graph-based workflows. Part of LangChain ecosystem.
- **Relevance:** Can model the aggregation pipeline as a directed graph — one node per source (Jira, GitHub, Slack, etc.), with edges controlling data flow to a summarization node.
- **MCP support:** No native MCP support yet (as of March 2026).
- **Effort estimate:** Medium-high. Requires Python development. Good for production-grade systems with fault tolerance.
- **Source URLs:**
  - https://blog.premai.io/open-source-agentic-frameworks-langgraph-vs-crewai-more/ (accessed 2026-03-26)
  - https://langfuse.com/blog/2025-03-19-ai-agent-comparison (accessed 2026-03-26)

### 3. CrewAI

- **What:** Role-based multi-agent framework. Agents collaborate as a "crew" with distinct roles (researcher, writer, reviewer).
- **Relevance:** Natural fit for a briefing PA — assign agents to each source (Jira agent, GitHub agent, Slack agent) and a summarizer agent to compile the briefing.
- **MCP support:** Has A2A (Agent-to-Agent) support. No native MCP.
- **Effort estimate:** Low-medium. Higher-level abstraction than LangGraph. Faster to prototype but less production-grade control.
- **Source URLs:**
  - https://zams.com/blog/crewai-vs-langgraph (accessed 2026-03-26)
  - https://developer.ibm.com/articles/awb-comparing-ai-agent-frameworks-crewai-langgraph-and-beeai/ (accessed 2026-03-26)

### 4. Goose (by Block)

- **What:** On-machine AI agent that works with any LLM and integrates via MCP servers.
- **Relevance:** Could serve as the runtime for a custom PA. Connect read-only MCP servers for each source and configure it to produce daily briefings.
- **MCP support:** Yes — native MCP integration.
- **Effort estimate:** Medium. Open source, extensible, but requires configuration and potentially custom MCP server development.
- **Source URL:** https://github.com/block/goose (accessed 2026-03-26)

### 5. OpenAgents

- **What:** Framework with native support for both MCP and A2A protocols.
- **Relevance:** The only framework with native support for both emerging standards, which could future-proof a custom build.
- **MCP support:** Yes — native.
- **Effort estimate:** Unknown — newer framework, less community documentation.
- **Source URL:** https://openagents.org/blog/posts/2026-02-23-open-source-ai-agent-frameworks-compared (accessed 2026-03-26)

## Section C: MCP Integration Effort

### General Effort Estimates

Source: https://www.intuz.com/blog/saas-mcp-integration-cost (accessed 2026-03-26)
Additional source: https://newsletter.pragmaticengineer.com/p/mcp-deepdive (accessed 2026-03-26)

**Development timeline:**
- Minimal MCP server (wrapping existing APIs): **1-2 weeks**
- Production-hardening (logging, monitoring, security, load testing): **+2-4 weeks**
- Total for production-ready server: **3-6 weeks**

**Cost estimates (Year 1):**
- Basic-to-medium complexity: **$9,200-$37,500** in Year 1
- Ongoing annual maintenance: **$4,200-$24,000/year** thereafter
- Budget **0.25-0.5 FTE per quarter** for MCP upkeep across multiple touchpoints

**DIY hosting costs:**
- Cloudflare Workers: $1-5/month for 100 users/day
- Proprietary alternatives: $300+/month

**Practitioner quote:** "It was very straightforward to build; we used Spring AI. The challenge is in optimising content served, not the MCP integration itself." — Principal Engineer at Miro (via Pragmatic Engineer newsletter)

### Key Consideration: Pre-built Servers Exist

For the specific integrations needed (Jira, GitHub, Google Workspace, Slack), **production-quality MCP servers already exist** — the build effort is primarily in orchestration, not in creating servers from scratch. See Section D below.

### Summary: MCP Server Availability

**All four target integrations have mature, production-quality MCP servers available.** Two of the four (GitHub official, korotovsky Slack) have explicit read-only modes as first-class features. The other two (Atlassian, Google Workspace) can be constrained to read-only via OAuth scope restriction.

This significantly reduces the build effort — the custom PA would primarily need:
1. An orchestration layer (n8n, LangGraph, CrewAI, or custom script)
2. A summarization prompt for Claude API
3. Configuration of existing MCP servers in read-only mode

## Section F: Key Risks and Considerations

### Build Risks
1. **Maintenance burden:** MCP servers and APIs evolve. Budget 0.25-0.5 FTE/quarter for upkeep.
2. **Token cost unpredictability:** Tool definition overhead (55-134K tokens/session) can dominate costs. Anthropic's Tool Search Tool can mitigate this.
3. **Authentication complexity:** OAuth flows for 4 different services require careful management, token refresh, and error handling.
4. **Cost overruns:** AI project cost overruns can reach 500-1,000% from pilot to production (source: https://sumatosoft.com/blog/ai-development-costs, accessed 2026-03-26).

### Buy Risks
1. **Feature gaps:** No single product covers all five integrations with a read-only/advisory model.
2. **Vendor dependency:** Pricing changes (see Atlassian Rovo's pricing shifts), feature removals, or service discontinuation.
3. **Integration depth:** "Broad but often surface-level integrations" is a recurring criticism of multi-tool platforms (source: Lindy.ai review).
4. **Credit-based pricing unpredictability:** Lindy, Relevance AI, Taskade all use credit systems where costs can spike unexpectedly.

### Industry Context
- "Organizations misestimate AI costs by more than 10%, with nearly a quarter underestimating costs by 50% or more" — 2025 survey (source: https://getdx.com/blog/ai-coding-tools-implementation-cost/, accessed 2026-03-26)
- Model costs have been dropping rapidly: processing 1M tokens went from ~$12 to under $2 between 2022-2024, trend continuing into 2026
- Claude Opus 4.6 at $5/MTok input is a 67% reduction from Opus 4.1 at $15/MTok
