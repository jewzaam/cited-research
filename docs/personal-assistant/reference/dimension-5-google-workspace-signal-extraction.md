## 1. Gmail: Unread Emails, Response-Awaiting, Action Items

### 1.1 Gmail API Capabilities

The Gmail API supports filtering messages using a query string (`q`) parameter with standard Gmail search syntax (e.g., `from:someuser@example.com is:unread`) and filtering by `labelIds` to return only messages matching specified labels.

- **Source**: [List Gmail messages | Google for Developers](https://developers.google.com/workspace/gmail/api/guides/list-messages)
- **Date accessed**: 2026-03-26

The Gmail API also supports advanced rules (filters) that evaluate incoming messages against criteria like sender, subject, or size, and trigger actions such as adding/removing labels or forwarding.

- **Source**: [Gmail API overview | Google for Developers](https://developers.google.com/workspace/gmail/api/guides)
- **Date accessed**: 2026-03-26

### 1.2 Gmail API OAuth Scopes for Read-Only Access

| Scope | URI | Access Level | Sensitivity |
|-------|-----|-------------|-------------|
| `gmail.readonly` | `https://www.googleapis.com/auth/gmail.readonly` | View email messages and settings | Sensitive |
| `gmail.metadata` | `https://www.googleapis.com/auth/gmail.metadata` | View message metadata (labels, headers) but not body | Sensitive |
| `gmail.labels` | `https://www.googleapis.com/auth/gmail.labels` | See and edit email labels (read+write) | Sensitive |

Best practice: use the most narrowly focused scope possible. For signal extraction that requires reading email bodies, `gmail.readonly` is the minimum. For metadata-only triage (sender, subject, labels), `gmail.metadata` suffices.

- **Source**: [Choose Gmail API scopes | Google for Developers](https://developers.google.com/workspace/gmail/api/auth/scopes)
- **Date accessed**: 2026-03-26
- **Quality note**: Official Google documentation; authoritative.

The `gmail.readonly` scope is classified as **restricted** -- apps using it must go through a security assessment and restricted scope OAuth App Verification.

- **Source**: [Restricted Scopes - Google Cloud Platform Console Help](https://support.google.com/cloud/answer/13464325?hl=en)
- **Date accessed**: 2026-03-26

### 1.3 Gmail API Rate Limits and Quotas

- Daily quota: 1,000,000,000 quota units per day (per project).
- Per-user rate limit: **250 quota units per user per second** (moving average; allows short bursts).
- Per-user limits **cannot be increased** by Google for any reason.
- Bandwidth limits match IMAP limits and are shared across all Gmail API clients for a user.
- Exceeding limits returns HTTP 429 "User-rate limit exceeded" with a Retry-After header.
- Batching is encouraged but batches larger than 50 requests are not recommended.

- **Source**: [Usage limits | Gmail | Google for Developers](https://developers.google.com/workspace/gmail/api/reference/quota)
- **Date accessed**: 2026-03-26

## 2. Google Calendar: Meetings, Conflicts, Prep Signals

### 2.1 Calendar API Capabilities

The Google Calendar API does **not** have a dedicated "conflict detection" endpoint. Conflict detection requires:

1. Listing events within a time range using `events.list`.
2. Programmatically comparing start/end times to detect overlaps.

For Focus Time and Out of Office events, the API provides a built-in `autoDeclineMode` field with values: `declineNone`, `declineAllConflictingInvitations`, `declineOnlyNewConflictingInvitations`.

- **Source**: [Google Calendar API Python Client docs](https://googleapis.github.io/google-api-python-client/docs/dyn/calendar_v3.events.html)
- **Date accessed**: 2026-03-26

Push notifications allow server-side applications to be notified when calendar data changes, enabling efficient monitoring without polling.

- **Source**: [Manage quotas | Google Calendar | Google for Developers](https://developers.google.com/workspace/calendar/api/guides/quota)
- **Date accessed**: 2026-03-26

### 2.2 Calendar API OAuth Scopes

| Scope | Access Level |
|-------|-------------|
| `calendar.readonly` | View calendars |
| `calendar.events.readonly` | View events on all calendars |
| `calendar.events` | View and edit events |
| `calendar` | Full access (see, edit, share, delete) |

For signal extraction (read-only), `calendar.events.readonly` provides sufficient access to list events, check for conflicts, and identify meetings without agendas.

- **Source**: [Choose Google Calendar API scopes | Google for Developers](https://developers.google.com/workspace/calendar/api/auth)
- **Date accessed**: 2026-03-26

### 2.3 Calendar API Quotas

- Quotas enforced per project and per user, calculated per minute using a sliding window.
- Two dimensions: per minute per project, and per minute per project per user.
- Exceeding quotas returns HTTP 403 ("usageLimits") or HTTP 429.
- Push notifications are recommended over polling for more efficient quota usage.
- All Calendar API usage is free; exceeding quotas does not incur charges.
- With domain-wide delegation, the service account itself is charged against per-user quotas (not the impersonated user), which can cause rate limiting.

- **Source**: [Manage quotas | Google Calendar | Google for Developers](https://developers.google.com/workspace/calendar/api/guides/quota)
- **Date accessed**: 2026-03-26

## 3. Google Drive: Unresolved Comments, Shared Docs Needing Review

### 3.1 Drive API Comment Management

The Drive API provides full CRUD operations on comments. Key details:

- Comments are either **anchored** (tied to a specific location and version) or **unanchored** (tied to the document only).
- The `comments.list` method retrieves comments for a file. The `resolved` field on the comment resource indicates whether a comment has been resolved.
- The `fields` system parameter **must** be set for all comment resource methods (excluding delete).
- A comment with its replies constitutes a "discussion."

- **Source**: [Manage comments and replies | Google Drive | Google for Developers](https://developers.google.com/workspace/drive/api/guides/manage-comments)
- **Date accessed**: 2026-03-26

- **Source**: [REST Resource: comments | Google Drive | Google for Developers](https://developers.google.com/workspace/drive/api/reference/rest/v3/comments)
- **Date accessed**: 2026-03-26

### 3.2 Extracting Unresolved Comments Programmatically

Using Google Apps Script with the Drive advanced service:

- `Drive.Comments.list()` fetches comments from a file.
- Scripts can filter for unresolved/active comments, extract replies, authors, and quoted text.
- Community efforts exist to build scripts that aggregate unresolved comments across multiple team documents into a single tracking sheet.

- **Source**: [Extracting unresolved comments from Google Docs and Sheets using Apps Script - Latenode Community](https://community.latenode.com/t/extracting-unresolved-comments-from-google-docs-and-sheets-using-apps-script/10341)
- **Date accessed**: 2026-03-26

### 3.3 Drive API: Pending Access Proposals

The Drive API also supports managing pending access proposals -- requests from users who want access to shared documents.

- **Source**: [Manage pending access proposals | Google Drive | Google for Developers](https://developers.google.com/workspace/drive/api/guides/pending-access)
- **Date accessed**: 2026-03-26

### 3.4 Drive API OAuth Scopes

| Scope | Access Level |
|-------|-------------|
| `drive.readonly` | See and download all Google Drive files |
| `drive.metadata.readonly` | View metadata for files in Drive |
| `drive.file` | Per-file access only (non-sensitive) |

For signal extraction, `drive.readonly` is needed to list files and read comments. The narrower `drive.file` scope only grants access to files created/opened by the app.

- **Source**: [Choose Google Drive API scopes | Google for Developers](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)
- **Date accessed**: 2026-03-26

### 3.5 Drive API Rate Limits

- Default: **20,000 calls per 100 seconds** (per project).
- Per-user default: **2,400 requests per 60 seconds** (adjustable by admin up to project quota).
- No daily limit provided you stay within per-minute quotas.
- Exceeding quotas returns HTTP 403 ("User rate limit exceeded") or HTTP 429.
- All Drive API usage is free.

- **Source**: [Usage limits | Google Drive | Google for Developers](https://developers.google.com/workspace/drive/api/guides/limits)

## 4. Google Docs: Suggested Edits, Comment Threads

### 4.1 Reading Suggestions via the Docs API

The Google Docs API supports reading suggestions through the `suggestionsViewMode` parameter on `documents.get`:

| Mode | Behavior |
|------|----------|
| `SUGGESTIONS_INLINE` | Pending deletions/insertions appear inline; correct indices for batchUpdate |
| `PREVIEW_SUGGESTIONS_ACCEPTED` | Preview with all suggestions accepted |
| `PREVIEW_WITHOUT_SUGGESTIONS` | Preview with all suggestions rejected |
| `DEFAULT_FOR_CURRENT_ACCESS` | Default behavior |

Style suggestions (formatting changes) are also readable, exposing fields like `suggestedTextStyleChanges` and `textStyleSuggestionState`.

- **Source**: [Work with suggestions | Google Docs | Google for Developers](https://developers.google.com/workspace/docs/api/how-tos/suggestions)
- **Date accessed**: 2026-03-26

### 4.2 Limitation: Cannot Create or Accept/Reject Suggestions via API

The Google Docs API **cannot** programmatically:
- Create suggestion-mode edits
- Accept or reject suggestions

This is a known limitation with open feature requests on Google's Issue Tracker:
- [Google Docs API Support for Suggested Edits (Issue #287903901)](https://issuetracker.google.com/issues/287903901)
- [Add Comments to the Docs API (Issue #298084084)](https://issuetracker.google.com/issues/298084084)

Comments on Docs documents must be managed through the **Drive API** (not the Docs API).

- **Source**: [Google Docs API Support for Suggested Edits - Issue Tracker](https://issuetracker.google.com/issues/287903901)
- **Date accessed**: 2026-03-26
- **Quality note**: These are open feature requests, indicating Google has not yet addressed these gaps.

### 4.3 Detecting Pending Suggestions

To detect whether a document has pending suggestions:
1. Call `documents.get` with `suggestionsViewMode=SUGGESTIONS_INLINE`.
2. Compare the returned content against the same document with `PREVIEW_WITHOUT_SUGGESTIONS`.
3. Differences indicate pending suggestions.

Alternatively, iterate through the document body looking for `suggestedInsertionIds` or `suggestedDeletionIds` fields on content elements.

- **Source**: [Work with suggestions | Google Docs | Google for Developers](https://developers.google.com/workspace/docs/api/how-tos/suggestions)
- **Date accessed**: 2026-03-26

## 8. Data Gaps and Unfound Items

1. **Gmail "awaiting response" detection**: No native API endpoint or label for detecting emails that specifically await the user's response. This would require heuristic analysis (e.g., last message was from someone else, no reply sent) or LLM-based analysis of email content.

2. **Calendar "meetings without agendas" detection**: No API field indicates whether an event has an agenda. Would need to check whether the event description is empty or whether attached documents exist.

3. **Calendar "prep needed" signal**: No native support. Would require custom logic (e.g., check if events have attachments, linked docs, or specific keywords in description).

4. **Drive "recent shares needing review"**: The `files.list` API with `sharedWithMe=true` and date filtering can approximate this, but there is no "needs review" signal from Google.

5. **Docs comment threads mentioning a specific user**: The Drive API `comments.list` returns comment content, but filtering by @-mentioned user requires client-side parsing of comment text. No server-side filter for mentioned users exists.

6. **Docs API comment support**: Comments on Google Docs are managed through the **Drive API**, not the Docs API. There is an open feature request (Issue #298084084) to add comment support directly to the Docs API.
