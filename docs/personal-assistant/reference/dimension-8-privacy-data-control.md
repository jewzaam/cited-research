## 1. Anthropic API Data Retention

**Default API retention:** 7 days (reduced from 30 days as of September 14, 2025). Inputs and outputs automatically deleted after 7 days. Never used for model training — flat policy, no opt-in/opt-out.

**Zero Data Retention (ZDR):** Available for qualifying enterprise API customers. Under ZDR, inputs/outputs are not stored at all beyond abuse screening. ZDR applies to eligible Anthropic APIs and products using the Commercial organization API key (including Claude Code).

**Exception:** Even with ZDR, Anthropic may retain data flagged for Usage Policy violations for up to 2 years.

**Consumer accounts (different rules):** Claude Free, Pro, and Max users can opt in to data training. If they don't opt out, retention extends to 5 years. This does NOT apply to API or commercial accounts.

## 3. MCP Architecture — Data Flow and Privacy

**Local MCP servers (stdio transport):** Data stays entirely on the local machine. No network traffic, no third-party involvement. This is the most private configuration.

**Remote MCP servers (Streamable HTTP):** Data flows from MCP client to MCP server over HTTPS. If the MCP server is first-party (e.g., Atlassian's hosted server at `mcp.atlassian.com`), data flows directly between your client and the platform provider — no additional third party.

**Privacy risk analysis:**
- Most secure: local/private AI + direct MCP/API integration to end services. Minimizes external touchpoints.
- Highest risk: cloud-based AI + middleware (e.g., Zapier) to end services. Multiple third parties see data.
- For Claude API + official MCP servers (Jira, GitHub, Google, Slack): data flows from local MCP client to each platform's API, then to Claude API for reasoning. Data path touches only (1) the platform's API and (2) Anthropic's API.

**Security concern:** 43% of publicly available MCP servers contain command injection vulnerabilities (per security research). This argues for using only official/first-party MCP servers.

## 5. Ensuring No Data Egress Outside Cited Platforms

To ensure data flows only between Jira, GitHub, Google Workspace, Slack, and Claude API:

1. **Use official/first-party MCP servers only** — Atlassian Rovo, GitHub MCP, Google Workspace MCP, Slack MCP. These connect directly to their respective platform APIs.
2. **Use stdio transport for local MCP servers** — data never leaves the machine except to call platform APIs.
3. **Use API (not consumer) Claude accounts** — ensures 7-day retention, no training, ZDR available.
4. **Scope OAuth tokens with least privilege** — read-only where possible.
5. **Audit MCP tool annotations** — the Nov 2025 spec added structured annotations declaring whether tools are read-only or can modify data.
6. **Use read-only mode** where available (e.g., GitHub MCP `--read-only` flag, korotovsky Slack MCP read-only by default).
7. **Consider ZDR** for enterprise deployments.
8. **Network controls** — firewall rules to restrict outbound connections to only the five allowed API endpoints.
