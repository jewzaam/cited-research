## 1. Model Context Protocol (MCP) — What It Is and How It Works

### What MCP Is

MCP is an open-source standard for connecting AI applications to external systems. The official site describes it as "a USB-C port for AI applications" — a standardized way to connect AI to data sources, tools, and workflows.

- **Source:** https://modelcontextprotocol.io/ (accessed 2026-03-26)

### Architecture

MCP uses a client-server model with three participants:
- **MCP Host** — the AI application (e.g., Claude Code, Claude Desktop) that coordinates MCP clients
- **MCP Client** — maintains a 1:1 stateful session with an MCP server
- **MCP Server** — exposes Tools (executable actions), Resources (readable data), and Prompts (reusable instructions)

Transport mechanisms:
- **stdio** — local processes on the same machine, no network overhead
- **Streamable HTTP** — recommended for production/cloud (replaced SSE as of MCP spec 2025-03)

- **Source:** https://modelcontextprotocol.io/docs/learn/architecture (accessed 2026-03-26)
- **Source:** https://www.anthropic.com/news/model-context-protocol (accessed 2026-03-26)

### Governance

Anthropic donated MCP to the Agentic AI Foundation (AAIF) under the Linux Foundation in December 2025, co-founded with Block and OpenAI. AWS, Google, Microsoft, Cloudflare, and Bloomberg joined as supporting members.

- **Source:** https://dev.to/universe7creator/the-complete-guide-to-model-context-protocol-mcp-building-ai-native-applications-in-2026-10c5 (accessed 2026-03-26)

### Ecosystem Scale

Over 97 million monthly SDK downloads, 10,000+ active servers, first-class client support across Claude, ChatGPT, Cursor, Gemini, Microsoft Copilot, VS Code.

### Spec Updates (Nov 2025)

Added async operations, stateless Streamable HTTP, OAuth 2.1 authorization, server-side `.well-known` URL discovery, and structured tool annotations (read-only vs. write).

## 5. Tool Use / Function Calling for Structured Output

Claude supports structured outputs with `strict: true` on tool definitions, guaranteeing schema-valid JSON. This enables reliable generation of typed action lists.

Advanced features (2025-2026):
- **Tool Search Tool** — search through thousands of tools without consuming context
- **Programmatic Tool Calling** — Claude writes code to call tools in an execution container, reducing latency and token consumption for multi-tool workflows
- **Tool Use Examples** — reference implementations demonstrating tool call patterns and conversation management

## 7. Best Practices for Prompt Design / Daily Briefing

Key recommendations:
- Create narrow, composable Skills: one job per Skill, use a router/orchestration Skill to combine
- Restrict subagents to specific tools (e.g., read-only) for data gathering
- CLI tools (`gh`, `curl`) are more context-efficient than MCP servers (no schema overhead)
- Limit MCP servers to those actively used (community reports: "went overboard with 15 MCP servers... ended up using only 4 daily")
- For daily briefing pattern: Research -> Plan -> Execute -> Review follows Command -> Agent -> Skill architecture

- **Source:** https://code.claude.com/docs/en/best-practices (accessed 2026-03-26)
- **Source:** https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices (accessed 2026-03-26)

## Gaps and Limitations

1. **No published reference implementation** — No end-to-end example of a Claude-based PA that reads from Jira + GitHub + Google + Slack and produces a prioritized action list. The pieces all exist, but no single reference implementation was found.
2. **Tool definition token overhead** — MCP tool definitions can consume 55-134K tokens per session before any data is processed. This is a significant cost driver.
3. **CLI tools vs MCP trade-off** — CLI tools like `gh` are more token-efficient but lack the structured tool interface that MCP provides.
