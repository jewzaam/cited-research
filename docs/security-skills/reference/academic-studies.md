# Academic Studies on LLM-Generated Test Quality

Covers: Peer-reviewed research on the quality, effectiveness, and limitations of
tests generated by large language models. See `../citations.md` for full source
details.

---

## Key Studies

### EvalPlus / HumanEval+ (NeurIPS 2023) [1]

**Finding:** Existing benchmarks drastically overestimate LLM code correctness
due to inadequate test suites.

| Metric | Reduction with HumanEval+ |
|--------|---------------------------|
| Greedy | up to 23.1% |
| pass@1 | up to 19.3% |
| pass@10 | up to 24.9% |
| pass@100 | up to 28.9% |

- HumanEval+ augments the original HumanEval benchmark by 80x test cases
- Found 18 defects (11% of problems) in original ground-truth solutions
- Corrected model rankings: WizardCoder-CodeLlama and Phind-CodeLlama
  outperform ChatGPT on HumanEval+ but not on original HumanEval
- Demonstrates that test inadequacy leads to mis-ranking of models

### MuTAP (Information and Software Technology, 2024) [2]

**Finding:** Mutation-guided prompting significantly improves LLM test quality.

| Dataset | MuTAP Mutation Score | Pynguin Mutation Score |
|---------|---------------------|-----------------------|
| Synthetic buggy code | 93.57% | N/A |
| HumanEval (164 tasks) | 94% | 66% |
| Refactory (1,710 bugs) | 94.9% detection | 67.5% detection |

- 17% of bugs undetectable by both Pynguin and zero-shot/few-shot LLM
  approaches
- Augments prompts with surviving mutants iteratively
- Uses Codex and llama-2-chat

### Copilot Test Generation in Python (AST 2024) [8]

**Finding:** Copilot test generation has low usability, especially without
existing test context.

| Context | Passing | Failing/Broken/Empty |
|---------|---------|---------------------|
| With existing test suite | 45.28% | 54.72% |
| Without existing test suite | 7.55% | 92.45% |

- 290 tests generated for 53 sampled tests from open-source projects
- Passing tests frequently "mimic" existing tests structurally
- TU Delft study (El Haji, Brandt, Zaidman)

### AI-Augmented Testing: Copilot for JUnit/Mockito (2025) [13]

**Finding:** AI-generated tests trade detection accuracy for speed and coverage
breadth.

| Metric | AI-Generated | Human-Written |
|--------|-------------|---------------|
| Bug detection rate | ~80% | ~90% |
| Code coverage | 75% | 60% |
| First-pass test accuracy | 85% | 95% |
| Time to write | 40% less | Baseline |

**Caveat:** These specific percentages appeared in search summaries but could
not be verified against the full paper text.

### Meta ACH System (FSE 2025) [10]

**Finding:** Mutation-guided LLM test generation works at industrial scale.

- 10,795 Android Kotlin classes across 7 platforms
- 9,095 mutants generated, 571 privacy-hardening test cases
- Engineers accepted 73% of tests
- 36% judged privacy-relevant
- LLM equivalent mutant detection: precision 0.79, recall 0.47
  (0.95/0.96 with pre-processing)
- Used Llama 3.1 70B

### Agentic Property-Based Testing (NeurIPS 2025 Workshop) [11]

**Finding:** AI agents can effectively write property-based tests that find real
bugs in production libraries.

- Evaluated across 100 popular Python packages
- Of 984 bug reports generated, 56% valid bugs on manual review of 50
- 32% valid and worth reporting to maintainers
- Found bugs in NumPy, SciPy, Pandas
- Used Claude Opus 4.1 with Hypothesis library

## Cross-Study Patterns

1. **Coverage-fault detection gap is consistent:** Every study that measures
   both coverage and fault detection finds the gap [1][2][8][13]
2. **Mutation-guided approaches outperform vanilla generation:** MuTAP [2] and
   Meta ACH [10] both show significant improvements when mutation feedback
   guides test generation
3. **Context dependency:** Test quality degrades sharply without existing code
   context [8] -- 45.28% vs 7.55% passing rate
4. **Scale is achievable:** Meta [10] demonstrates industrial deployment across
   thousands of classes

---

## Gaps and Limitations

- No longitudinal studies tracking AI-generated test quality over multiple
  releases
- Limited comparison across different LLMs on the same codebase
- Most studies use open-source benchmarks; enterprise/proprietary code results
  are scarce (Meta [10] being the notable exception)
- The JUnit/Mockito study [13] metrics (80%/90% bug detection) could not be
  verified against the full paper
